Tested end to end, Windows 11 · August 2026

Edit video with Claude Code and Remotion

The short version going around is 3 steps. I ran all 3 on a clean machine and none of them got me to a rendered video. Here is the sequence that did, plus the 4 places it breaks on Windows and what each error actually means.

What you end up with: a real .mp4 that a React file generates, edited by asking for changes in plain English. No timeline scrubbing. Free for teams of 3 or fewer.

Before you start

  • Node.js — node --version should print something. Tested on v24.18.0.
  • Claude Code, in the folder you are about to create.
  • Windows only, and this one matters: put the project somewhere shallow, like C:\dev\video. Not inside a deep Documents or OneDrive tree. Reason in gotcha 4.

The sequence

1 · Scaffold the project

npx create-video@latest --yes --blank --no-tailwind video
cd video
npm install

Roughly 360 packages. --yes keeps it non-interactive so you are not answering template prompts.

2 · Install the Remotion agent skills

This is the step the 3-step version skips entirely, and without it Claude is guessing at Remotion's API instead of following it. The documented command is:

npx remotion skills add
On Windows this fails with Error: spawn EINVAL. It is not your setup. Run the command it wraps instead:
npx skills@1.5.20 add remotion-dev/skills --global --copy --skill "*" --agent claude-code --yes

That installs 12 skills — create, markup, captions, studio, render, interactivity, maps, multimedia, docs, saas, upgrade, best-practices. --global puts them in your user profile so every future project has them. --copy writes real files instead of symlinks into the project, which is what you want if the project folder ever moves or gets deleted.

3 · Get the render browser

npx remotion browser ensure

Pulls a 113 MB Chrome Headless Shell. Skip it and your first render dies on ENOENT pointing at an .exe that was never downloaded.

4 · Ask for the video

Open Claude Code in the project folder and describe what you want, in normal words. There is no special command to type. The skills you installed in step 2 activate on their own.

Use the two files in my downloads — clip.mov and hero.png.
Build a 9:16 split screen: image across the top 30%,
video filling the bottom 70%, captions on the split line.
Open the studio when it is done.

Claude writes a React component, registers it as a composition, and starts the preview. Ask for revisions the same way — "make the image fill more of the top", "go back to 16:9" — and the studio hot-reloads.

5 · Preview and render

npx remotion studio --no-open      # preview at localhost:3000
npx remotion render MyComp out.mp4 # write the file

A 10-second 1080×1920 composition rendered in well under a minute and came out at 8.8 MB.

The 4 things that break, and what the error means

SymptomCauseFix
spawn EINVAL from remotion skills add It calls npx.cmd without a shell. Node blocks that on Windows since the CVE-2024-27980 patch. Run the underlying npx skills@… command from step 2.
Render fails, ENOENT on chrome-headless-shell.exe The render browser was never downloaded. npx remotion browser ensure
Same ENOENT — but the file is on disk MAX_PATH. Windows caps paths at 260 characters. A deep project folder pushed the shell's path to 308 and Node could not launch it. Move the project somewhere shallow. C:\dev\video keeps the full path near 139.
A slash command you saw in a video does not exist Commands tagged (user) in the autocomplete are that person's own, stored in their ~/.claude/commands/. They do not ship with anything. Skip it. Describe what you want in plain language instead — step 4.

Worth knowing before you commit an afternoon

  • Remotion is free for teams of 3 or fewer; larger teams need a licence.
  • The composition is a real React file you own. When the agent gets something wrong you can open it and fix it directly.
  • Renders happen locally, so long videos take real minutes and real CPU.
  • Structure the markup the way the remotion-interactivity skill describes and edits you make in the Studio write back into the code.
Everything above was run on a clean Windows 11 machine in August 2026. Version numbers and error strings are the ones that came back, not recalled from documentation.
